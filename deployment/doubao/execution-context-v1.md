# 部署执行身份与本机边界

这是公开源码安装、离线安装和中断恢复的共同前置规则。先执行本文件，再执行对应安装步骤。产品与验收基线仍保留；基线中交给开发者的操作任务不作为豆包重新开发或操控另一个豆包的指令。

## 当前执行者

你就是用户正在对话的豆包，负责使用当前任务实际提供的工具部署和运行架构上岸教练。你不是 Codex，也不是负责打开另一个豆包的外部安装人员。不要启动第二个豆包会话、在虚拟桌面登录豆包、向另一个豆包转发部署提示词，或要求另一个豆包替你完成任务。

读取 `02_交给Codex的总执行指令.md` 时，只提取产品职责、验收要求和保留约束；其中开发、Phase 0 审计、操作豆包客户端等是开发者历史任务，不在接收者安装时重做。

## CONTEXT_CHECK：先确认在哪台电脑执行

**首次安装不等于全盘找旧项目。** 未收到明确恢复指令/路径时，只通过当前任务的本地执行目标确认本机，随后从用户提供的公开 URL 下载到本次独立新目录并读取入口。不要扫描主目录、桌面、Downloads、git-projects 或开发历史来推断是否安装过；也不要读取碰巧发现的 Codex 仓库、旧交付包、QA/归档目录。网盘授权资料核查只在后续资料步骤限定两个目录进行。发现同名旧技能时只核对官方技能目录中的这九个目标及其安装绑定，不扩散搜索；来源不明时询问是否恢复，不能读取其它项目。

源码 ZIP 含中文文件名，Mac 使用 Python 标准库 `zipfile` 解压到独立新目录，不使用交互式 unzip。报写入错误先核实真实磁盘空间和解压错误，不能直接归因磁盘已满。用户要求停止时仅停止当前工具任务或已核实属于本次操作的进程 ID；不要按通用进程名批量终止，不使用 `pkill unzip` / `pkill -f unzip`，不清理其它程序的工作。

1. 从当前工具明确提供的执行目标确认是否为用户这台 Windows/Mac 的「本地电脑」。不能仅凭聊天文字、操作系统名称或一个存在的目录推断为本机。
2. 使用本地工具只读查看用户指定的项目/压缩包路径，或确认本机安装目标目录；目录尚不存在可以在本机下载阶段创建。来自虚拟机、云端沙盒或上一台电脑的路径不算本机证据。
3. 如果工具目标不明确、仅有云电脑/虚拟桌面，或无法确认访问用户本机，输出 `NEEDS_LOCAL_MODE`。不在虚拟环境继续下载、安装、创建状态库或登录豆包。请用户回到豆包桌面客户端，新建工作任务并选择「本地电脑」，再发送原链接/包路径和恢复提示词。不能承诺提示词能切换当前任务的工具环境。
4. 使用云端飞书连接器不等于使用云电脑；本地任务可以调用已授权连接器。第三方登录和系统授权仍由本人完成。禁止复制 Cookie 或令牌来打通桌面与虚拟浏览器的登录态。

## 工具失败与有限重试

同一能力最多检索两次工具定义。取回 schema 不是成功调用：必须有实际目录、记录或页面结果才能记成功。已取回定义仍无法实际调用时，报告 `CONNECTOR_NOT_CALLABLE`，停止重复检索；不要连续说“立即调用”却继续搜索。记录失败并继续独立的状态/本地资料步骤，必要时给具体用户授权动作，不能卡在同一检索循环。

电脑 GUI 不可用不代表独立浏览器工具也不可用。需要网页时单独读取并核对当前「操作浏览器」能力与官方用法；不要以电脑环境初始化失败直接宣布浏览器也不可用。只能访问实际提供且已授权的目标，禁止用网页豆包替代自身操作。

## 自身界面不可操作时

先按 `folder-skills-v1.md` 核对官方创建技能的文件夹发现流程。若当前环境实际支持，可由豆包完成九技能文件夹安装与本机绑定，不必先要求用户逐个上传 ZIP。此为公开随附指南定义的扩展方式，不是客户端内部存储操作；仍须真实发现/调用验证，不声称账号云端技能或侧边栏项目自动创建。

当前任务若不能操作豆包自身的项目菜单、技能导入或本地模式选择，输出 `NEEDS_USER_UI`，只请求当前缺少的一个具体点击动作。例如「请在桌面客户端的项目菜单创建私有项目，并告知名称」或「请在个人技能中导入这个本机 ZIP」。若当前版本入口不同，让用户提供可见界面，不猜测按钮或完成状态。

当前已观察到的 Mac 项目编辑只有名称和本地文件夹。没有指令字段且没有项目文件入口时，使用技能安装绑定定位本机系统指令，不要求用户找不存在的上下文字段；侧边栏项目可作为用户选择的额外导航入口，但其缺席必须明确记录。

不要将打开豆包官方网站、创建网页任务或开启虚拟桌面作为自身界面操作的降级路径。不要尝试绕过平台禁止控制自身窗口的限制。让用户操作后，在当前任务能力范围内回读验证；不能验证则保留未确认状态。其它互不依赖的本机检查可以继续，但不能把项目创建、技能安装或持久绑定标为完成。

## 中断恢复，不重复部署

- 只有用户明确选择恢复/给出安装路径，或本次目标中已有可核实的安装回执时才进入恢复。初次链接请求没有本次安装目标前，不进行历史部署搜索。不存在恢复授权不能被解释为“先搜全盘再判断”。

- 先确认本机执行目标，再回读当前用户本机的 `dist/deployment/project-state.json`、`dist/bootstrap/public-source.json`（若存在）及实际已完成步骤。不要覆盖这些文件来强行重启安装。
- 原任务在虚拟环境下载的文件不能默认为本机已有。本机没有源码时重新从用户给定公开源下载；已有文件先核对来源，不覆盖未知目录。
- 已创建项目、已安装技能和当前用户的飞书 Base 先核对，不删除、不重复创建。只恢复用户确认属于本次部署的对象；同名不能证明是同一项目，多候选时询问用户。
- 已有画像和学习状态保持原样；仅在新用户且没有既有绑定时初始化空档案。所有写入仍遵守幂等与回读协议，不把读取失败当作不存在。
- 记录实际完成、待用户点击、未验证的步骤；本地脚本 PASS 不代表豆包在线部署完成。用户点击辅助不等于纯提示词全自动部署通过。
