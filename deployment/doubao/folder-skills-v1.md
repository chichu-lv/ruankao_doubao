# 官方文件夹技能安装与本机绑定

先读 `execution-context-v1.md`。本流程使用当前豆包随附「创建技能」指南所定义的扩展目录，不读写客户端数据库，不调用未公开接口，也不操控第二个豆包。

## 1. 解析当前环境，不能硬编码开发机路径

读取当前实际提供的 `skill-creator-for-work/SKILL.md`（若名称不同，以实际「创建技能」入口为准）。当前指南规定普通技能文件夹置于当前环境已存在的 `workspace/.user_skills`，父路径因系统/环境而异。根据当前技能路径定位这个目录；不能搜索其它账号配置、读取凭据或改用 Codex 的技能目录。

只有确认是本地电脑的官方技能发现目录后才继续。找不到或当前指南不支持此路径时，报告 `NEEDS_USER_UI` 并使用当前真实界面支持的 ZIP 上传路径，不把猜测路径当作已支持。

## 2. 一次安装九个文件夹

完成 BUILD 后，由豆包在实际项目根目录运行：

```text
<项目私有 Python> scripts/install_doubao_folder_skills.py --skill-root "<当前官方 workspace/.user_skills 目录>" --request-id "<本次安装请求 ID>"
```

Windows 私有 Python 为 `.runtime\python\python.exe`；Mac 为 `.venv/bin/python3`。由豆包执行，不要求用户手输命令。安装范围只包括清单中的九个精确技能目录；需要额外权限时说明这九个目标并请求授权。

安装器保留普通文件夹，给每个技能加入 `references/installation.json` 和先读绑定的指令。绑定包含本机真实项目根目录，后续再读该根目录的系统指令与 `dist/deployment/project-state.json`，不复制旧 Base 或用户历史。

同内容同绑定重复运行只复用；不同内容/不同项目绑定在写入前停止。不要偷偷删除或覆盖同名技能，不把旧技能发现当成本轮新安装证据。ZIP 仍是手工导入的备用交付格式，不代表文件夹创建流程要求 ZIP。

## 3. 持久入口与真实验证

`FILES_READY_DISCOVERY_UNVERIFIED` 只表示文件已就位，绝不等于账号云端安装或新会话发现通过。

- 在当前工具能力内重新发现/读取九个技能并核对绑定；缓存未刷新时如实保留待验证。
- 用户下一次新建「本地电脑」任务，只发送日常启动口令，不再提供安装路径。主控应从自身安装绑定自动定位系统指令和状态库，读取真实 checkpoint；必须实际执行这一测试后才声称无路径恢复可用。
- 各技能只使用本次绑定。当前工作目录是新聊天目录时也不能丢失项目位置。绑定文件缺失则明确报告，不猜同名 Base。
- 此方式提供本机持久技能和私有工作区，不等于创建了豆包侧边栏项目、配置了原生工作伙伴或同步到另一台设备。报告必须区分这些状态。

## 4. 豆包侧边栏项目

如果用户需要侧边栏容器、当前自身 UI 又不可操作，只请求一个普通用户动作：在「项目 → 创建新项目」填写名称，并用「添加本地文件夹」选择**本次实际项目根目录**。给出完整路径以及文件选择器操作，不让用户找不存在的控件。

当前已观察到的 Mac 项目窗口只有名称与本地文件夹，没有可见性选项、系统指令字段或单独项目上下文上传入口。不能要求用户设置这些不存在的字段，也不能把聊天附件说成项目级绑定。系统指令由技能安装绑定读取；无法创建侧边栏项目时可保留本机工作区作为等价持久入口，但必须标明原生项目未创建，并通过上节新会话验证，不伪造原生配置成功。

## 5. 清理与新用户验收

只有用户明确授权清理本项目后才删除。除相关项目、对话、记忆、状态库、提醒和界面技能外，还要按当前官方路径核对九个同名技能文件夹。界面消失不等于文件夹源已消失；不能仅凭数量下降判定干净。只处理精确目标，保留其它技能和其它项目。

清理前记录本轮对象与证据；清理后同时核对实际文件夹和新任务技能发现清单。任一渠道仍有旧项目技能就不算干净；开发核查对话和探针也应在下一轮前移除。测试账号已有共享登录和系统工具的限制必须继续记录。
